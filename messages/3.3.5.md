## PolyOS Editor v3.3.5 — self-heal stale syntax references

- **No more "Error loading syntax file" on startup.** Views restored from a
  pre-bundle session could still point at the old syntax paths
  (`Packages/User/polymark.sublime-syntax` or
  `Packages/PolyMark/polymark.sublime-syntax`), which no longer exist —
  Sublime logged `Unable to stat` every launch. The auto-sync plugin now
  rewrites any such view to the current
  `Packages/PolyOS-Edi-for-Sublime-Text/polymark.sublime-syntax`.
- On the next startup the error is already gone; existing buffers are fixed
  in place and the corrected syntax is saved back into the session.
- No keybinding or profile changes otherwise.

If the error still shows once immediately after upgrading, quit Sublime and
delete `Local/Session.sublime_session` (and `Workspace.sublime_workspace`) in
your `%APPDATA%\Sublime Text\` folder — the self-heal handles everything from
then on.
