## PolyOS Editor v3.3.6 — repair stale syntax the moment a view opens

- **Catches project/workspace restores too.** The v3.3.5 self-heal ran at
  startup and on a timer over already-open views. A buffer restored from a
  saved `.sublime-workspace` after startup still carried the old
  `Packages/User/polymark.sublime-syntax` path and logged the error again.
  The auto-sync plugin now repairs any such view immediately when it loads,
  so the error cannot reappear from a project or workspace — ever.
- No keybinding or profile changes otherwise.

If you still see the error once immediately after upgrading, quit Sublime and
delete `Local/Session.sublime_session` (and `Workspace.sublime_workspace`) in
your `%APPDATA%\Sublime Text\` folder — after that the self-heal keeps
everything clean on its own.
